# Step 29B verification

Verified on 2026-10-03 with Node 24.12.0, pnpm 12.3.4, Astro 7.3.1 and local
Linux/arm64 Docker images in branch `codex/step-29-build-site-guidance`.

## Method

`node scripts/generated-project-acceptance.mjs publication-visibility` builds the
workspace, verifies generated snapshots, packs 12 Lace packages, generates a
consumer outside the engine checkout, installs it from the tarballs and runs the
existing Node journey (migrate, sync, bootstrap, first admin, publish, Astro build
and typecheck) and Compose production smoke. The visibility phase then:

- starts generated `pnpm dev` and an independent existing Astro site with its own
  lockfile whose pages read the SDK export in page code, with post entries passed
  through `getStaticPaths` props;
- publishes changed Home and post titles, saves a draft-only title, publishes a
  new post slug, restarts both dev servers and renames that slug;
- observes each dev server on reload, `site/dist` before and after `pnpm build`,
  and the Compose web proxy while sampling build history;
- checks rendered HTML for the build token and other acceptance secrets.

Astro 7 detects agent environments and backgrounds `astro dev`; the harness sets
`ASTRO_DEV_BACKGROUND=1` with `--ignore-lock` so it owns and stops the processes.
`LACE_VISIBILITY_OBSERVE=1` records without asserting.

| Mode | Publish existing routes | Draft save | New slug |

| Generated dev | `/` and post **stale** on reload | hidden | 404 until restart |

| Compose | `absent > pending:old > pending:new > succeeded:new` | no build | served after build |

Served HTML had `ETag` and `Last-Modified` but no `Cache-Control`. The generated
loader memoized its first export for the dev process; Astro dev caches
`getStaticPaths` until a source change or restart. VPS build rows stay `pending`
during the synchronous builder call; success is recorded after the release switch.

## Result after changes (template 0.8.0)

All 35 observations matched their expectations:

- Generated dev: Home and the existing post updated on reload without restart; a
  draft stayed hidden; a new slug returned 404 until restart, then rendered; a
  renamed slug's old URL returned 404 instead of stale content.
- Independent dev (characterization of a user-owned integration): page-code reads
  updated on reload; props-based post content, new routes and renamed slugs kept
  their startup state until restart.
- Manual static: publication left `site/dist` unchanged; a fresh build contained
  it and excluded draft-only text.
- Compose: publications queued builds, draft saves did not; the proxy switched to
  new content only through a covering build (`pending` while building, then
  `succeeded`, briefly after the switch); responses carried
  `Cache-Control: no-cache` with `ETag`/`Last-Modified`.
- No build token or acceptance secret appeared in dev, static or served HTML.
